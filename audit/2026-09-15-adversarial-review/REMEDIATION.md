# 对抗性审查整改记录

整改日期：2026-09-15
原则：先修阻断价值链的问题；不引入新框架、微服务或数据库；每项修复必须能被测试或界面证据验证。

## 核心结论逐项整改

| 原结论 | 状态 | 本轮处理 | 验证方式 |
|---|---:|---|---|
| 模板中心是安慰剂 | 已修复 | 模板成为可执行 Recipe 预设，会切换公共模板、启用词组和场景规则；用户手动改配方后取消“当前模板”状态 | A1 通过；提示词和确认指纹均变化 |
| 数量 ×N 制造重复付费请求 | 已修复 | 每个重复数量生成明确、可追溯的变体目标，不再复制相同提示词 | A2 通过；默认 18 个任务得到 18 份唯一提示词 |
| 结果没有可执行验收 | 已建立最小闭环 | 每张结果必须填写结构保真 0–5、地域、景别、缺陷、可交付五项；系统自动得出待验收/通过/不通过，仅通过项可归档 | `deriveReview()` 单一判定规则；保存按钮由通过数控制 |
| 本地与线上生成能力分叉 | 已修复 | 本地服务把同一组 `/api/openai/*`、`/api/qwen/*` 请求代理到线上 Worker，前端不再分两套生成契约 | Python 静态与回归测试 |
| 本地状态文件不写入 | 已修复 | 本地主机确认支持写入后，前端使用 `PUT /api/state`；IndexedDB 为浏览器主存储，localStorage 仅保留小状态回退 | 状态往返测试通过 |
| 导出中心未实现 | 已修复 | 可按全部素材、SKU 或批次筛选，导出原格式/JPEG/PNG/WebP ZIP，并附完整 `manifest.json` 追溯清单 | ZIP 单元测试通过 |
| “4K”误导为新增细节 | 已修复文案与边界 | 统一改名“4K 尺寸版/导出”，明确为浏览器插值、不增加模型细节、不扣积分 | 前端回归测试与界面文案 |
| 失败仍扣固定积分 | 已修复当前演示账本 | 提交异常、异步失败、取消和未知任务会自动退回本地计划积分；4K 尺寸处理不扣分 | 前端回归测试 |
| 密钥通过即宣称模型可用 | 已修复 | 成功文案只确认基础身份；模型权限和额度明确由首次真实生成确认，供应商错误原样保留 | Worker 与前端契约测试 |
| 缺少超时、追踪与可观察性 | 已修复 | 所有供应商请求有分级超时；每次 API 请求带请求 ID，响应回传 `X-Request-Id`，Worker 输出脱敏结构化日志；客户端任务带稳定请求 ID | Worker 集成测试；Wrangler observability 配置 |
| 缺少跨实例强幂等 | 待后端存储 | 当前已阻止同页重复提交并保留任务请求 ID，但无 KV / Durable Object，无法承诺 Worker 跨实例去重；不以进程内 Map 冒充可靠幂等 | 明确保留为生产化边界 |
| 前端领域逻辑集中 | 部分完成，边界已建立 | 新增 `core.js`，集中组合、成本、模板、提示词、确认指纹和验收判定纯函数；新增 `export.js` 独立处理交付 | 结构消融直接调用 Core；ZIP 独立测试 |
| 未加载的旧 `app.js` 漂移 | 已修复 | 删除旧实现，入口只加载 Core、Export 和当前界面 | 静态文件测试 |
| 设计规范互相冲突 | 已修复 | 根 `DESIGN.md` 成为唯一规范；旧路径改为指针，不再维护第二套颜色、字体和页面结构 | 文档检查 |

## 仍需真实图片验证的边界

结构消融只能证明规则真实进入请求，不能证明模型一定服从。地域命中率、景别占比和产品结构保真仍需按原报告的 2×2×2、32 张真实图片方案盲评。该实验会调用付费模型，因此本轮未自动执行，也不把三项能力写成“已验证质量”。当前验收字段和导出清单已具备记录实验结果所需的数据结构。

## 2026-09-15 地域背景专项修复

- 地域从普通组合词提升为前置硬约束，明确参考产品图的白底、透明底、摄影棚和旧场景必须被替换。
- 悉尼、墨尔本、迪拜、苏州、伦敦与巴黎改为单一、可命名、可辨形的地标方案；加利福尼亚改为成组的建筑与植被识别特征，不再提供模型容易忽略的泛化备选。
- 近景、中景、远景分别规定地域锚点的最低可见面积；普通草坪、无名住宅、错误城市和过度虚化进入负面提示词。
- 千问精细模式保留 Pro 模型，但关闭自动提示词扩写与深度改写，使经用户确认的最终提示词原样进入模型请求。
- 自定义城市助手只输出一个最有把握的方案，并包含地标中英文名、外形特征、合理机位、最低占比与禁用替代背景。
